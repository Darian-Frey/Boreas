# Bugs

Catalogue of bugs discovered during development. Per Maintenance Rule 8,
bugs are logged here when found, not silently fixed. The author decides
whether to fix immediately, defer, or leave alone.

Status vocabulary: open | fixed | wontfix | deferred.
Severity vocabulary: low | medium | high.

## Open

### BUG-001: Panel mockup disagrees with SPEC.md §Layout and clips its column tabs
**Status:** open
**Found:** 2026-10-10 (filing the mockup into `design/`)
**Location:** `design/panel-mockup.png`
**Severity:** low
**Description.** The mockup was drawn in a browser with web fonts and doesn't follow the layout grid. SPEC.md §Layout is authoritative for now. While the mockup is wrong it can't serve as the Phase 1 photographic reference (ROADMAP Phase 1 acceptance, AV-007). Differences, measured in panel pixels (the image is 1600×1200, 4× native, despite the "2×" in its original filename):
- Header and column tabs merged into one black block at y 5–38. SPEC has a 20 px header (y 5–25) and separate 12 px tabs from y 26.
- Tab text `EXT · OUTDOOR` and `OPEN-METEO` wraps and is clipped at the bottom of that block.
- Column dividers at x 150 and x 270 (SPEC: 151 and 272).
- Bottom strip starts at y 192 (SPEC: 200); footer at y 280 (SPEC: 283).
- No divider between the temperature trace and the rain meter; the meter starts at about x 269 (SPEC: trace is 250 px wide).
- Outdoor hero temperature is about 34 px tall (F-002 requires at least 48 px).
- Header clock shows seconds (`13:30:07`); the default build is HH:MM (D-008).
- `FEELS · HI · LO` wraps onto two lines (F-002: one line).
**Reproduction.** Open `design/panel-mockup.png` beside SPEC.md §Layout.
**Notes.** Plan (D-016, 2026-10-10): replace the mockup as the Phase 1 reference with a PNG generated by the host preview build, which renders the real `ui/` code with U8g2's fonts. The mockup stays in `design/` as the style reference. Closes once the first generated reference is committed. If the redraw shows SPEC is the one that's wrong, update SPEC.md §Layout and close this entry.

## Fixed

### BUG-003: SPEC's USB-present rule can never fire
**Status:** fixed
**Found:** 2026-10-10 (writing `src/sensors/Battery`)
**Location:** SPEC.md §Battery; future footer/Diag battery display (F-007)
**Severity:** low
**Description.** SPEC.md says "USB present if `V_batt` reads > 4.15 V while CHG is lit". Measured on the board in Phase 0, `V_batt` on USB while charging is 4.12–4.14 V, so the rule never triggers. The firmware also can't see the CHG LED: there's no known GPIO for it. As written, the footer could never show mains power, and Phase 3 couldn't tell battery from mains by voltage alone.
**Reproduction.** USB connected, cell charging: `BATT 4.12 V` on serial (bring-up or firmware scaffold).
**Notes.** Not implemented in `Battery`, which reports volts, cells and LOW/HALT only. Options: (a) check the Waveshare schematic for a VBUS or CHG signal on a free GPIO; (b) infer USB from the native USB being enumerated (works only when plugged into a computer, not a wall charger); (c) infer from voltage *trend* (rising = charging); (d) drop the indicator. Needs a decision before F-007's footer battery display.
**Resolution.** 2026-10-10: option (d) chosen. The USB-present rule is removed from SPEC.md §Battery, and the footer shows voltage and gauge only (F-007 never required an indicator). The hardware route (a 100 kΩ/100 kΩ divider from header P1-2 VBUS to GPIO1, P1-7) is noted in ROADMAP Phase 3 in case power policy later needs to know about mains.

### BUG-002: Oscillator-stop flag clear does not mean the RTC time is valid
**Status:** fixed
**Found:** 2026-10-10 (Phase 0 bring-up, first run of `test/bringup`)
**Location:** cross-cutting: D-007, F-009, AV-005; future `src/sensors/` RTC reader
**Severity:** medium
**Description.** The new board's PCF85063 read `2026-01-05 14:32` on 2026-10-10 with the oscillator-stop (OS) flag clear. D-007 and F-009 treat "OS flag clear" as "RTC OK". By that rule the footer would show `RTC OK` beside a clock that's nine months wrong, and on a boot with no Wi-Fi the panel would show that wrong time and date with no warning.
**Reproduction.** Fresh board, no NTP sync yet: flash `test/bringup` and read the `RTC` line.
**Notes.** Possible rules, each needing a D-007 amendment: (a) also require the year to be at least the firmware build year/month; (b) keep a "set by NTP" marker in the PCF85063's spare RAM byte (register 0x03) and only report `RTC OK` when it's present and the OS flag is clear; (c) both. Option (b) also survives battery swaps if the backup cell is fitted. The bring-up test only resets the RTC when the OS flag is set, so it left the stale time alone.
**Resolution.** 2026-10-10: option (b) adopted as D-015 (OS flag clear **and** NTP marker in register `0x03`). Spec, F-009 and SPEC.md §RTC updated. Enforced in code when `src/sensors/` RTC support is written in Phase 1.
